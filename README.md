# Job-RAG

AI 招聘岗位知识库（基础数据准备阶段）。

## 数据来源与范围

来源：`BOSS直聘_AI岗位数据库_清洗规整版_20261024` 中的 **「历史_岗位去重总表」**。本次静态快照共 593 条职位记录，其中 325 条有非空岗位描述，268 条没有岗位描述。

数据仅供学习、研究与分析。职位状态、薪资及招聘要求可能发生变化，不保证仍在招聘。

## 数据结构

```text
data/
├── jobs_with_details.csv       # 325 条：有岗位描述
└── jobs_without_details.csv    # 268 条：无岗位描述
```

- `data/jobs_with_details.csv`：325 条有岗位描述的记录，供后续语义检索与向量化。
- `data/jobs_without_details.csv`：268 条无岗位描述的记录，供结构化查询及后续补采。
- 两个文件合起来是全部 593 条岗位的**唯一基础数据源**，不再保留旧分片。
- CSV 首行为字段名，其余每行一条岗位记录，以 `job_id`（来源于「职位ID」）作为稳定标识，包含职位名称、公司、地区、薪资、经验、学历、原始链接、采集状态、采集日期、关键词和岗位描述等。
- 没有岗位描述的记录依然保留，便于后续补充采集和精确筛选。
- 不另行维护 `documents` 目录。后续构建向量索引时，直接读取 `jobs_with_details.csv`，按需组合岗位标题、工作区域、任职要求等文本，生成 Embedding；生成的检索文本属于可重建的中间数据，不作为第二份事实来源。

两个 CSV 文件均采用 UTF-8 with BOM 编码，符合标准 CSV 引号转义规则；包含换行的岗位描述仍属于单个 CSV 单元格。读取时建议使用支持标准 CSV 解析的工具，而非自行按换行拆分。

## 更新与检索约定

1. 以 `job_id` 做新增或更新（upsert），不要用分片文件名或行号作为岗位标识。
2. 向量化只针对具备有效岗位描述的数据；具体过滤规则在建索引脚本中实现。
3. 当岗位描述有变化时，重新生成该岗位的向量；删除的岗位应同步从索引中移除。
4. 地区、薪资、工作经验、学历等适合结构化条件过滤；岗位职责、技术要求等适合做语义检索。
5. 当前没有创建 Embedding 向量、向量库或检索服务。

## 数据与隐私

此仓库为公开仓库。数据只包含知识库使用所需的岗位字段，不含招聘者姓名/活跃信息、企业工商登记原文等非必要字段。原始 Excel 应自行妥善保管；请勿上传 API Key、个人简历或其他私有信息。
