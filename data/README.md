# 原始岗位数据

本目录保存外部采集流程提供的岗位 CSV，是知识库的数据输入，不是清洗结果、检索索引或模型输出目录。

```text
data/
├── README.md
└── jobs.csv       # 原始岗位数据
```

## 1. 数据来源与系统边界

项目没有把招聘网站爬虫和 RAG 系统绑在一起。它假设招聘数据已经通过外部流程采集，并整理成标准 CSV，然后再导入知识库。

```text
外部采集 → 标准 CSV → 导入与版本记录 → 派生结构字段、分块及可选 Embedding → 检索与证据分析
```

采集流程负责取得招聘页面文字与来源信息；Job-RAG 负责导入、保留原文、生成派生数据及提供可追溯检索。采集成功不意味着岗位目前仍在招聘，来源页面中的说法也不等于已经独立核验的事实。

## 3. 字段说明

当前 CSV 的全部 16 个字段如下：

| 类型 | 字段 | 作用 |
|---|---|---|
| 身份标识 | `job_id` | 来源内的岗位标识，用于去重、增量更新和版本关联 |
| 基本属性 | `title` | 原始岗位名称 |
| 基本属性 | `company` | 原始公司名称 |
| 基本属性 | `location` | 原始地点文字，用于派生城市、区等筛选字段 |
| 基本属性 | `address` | 补充的工作地址信息，可能为空或未明确显示 |
| 招聘条件 | `salary` | 原始薪资文字，用于派生金额区间、计薪周期等硬筛选字段 |
| 招聘条件 | `experience` | 原始经验要求，用于派生经验年限等条件 |
| 招聘条件 | `education` | 原始学历要求，用于派生学历筛选字段 |
| 非结构化文本 | `description` | 完整 JD 原文，是 RAG 检索和条件判断的主要依据 |
| 来源信息 | `url` | 原始岗位链接，供溯源与后续复核 |
| 来源信息 | `collected_at` | 外部采集时间，不是最近核验招聘状态的时间 |
| 采集信息 | `status` | 外部采集结果，例如“已获取描述”“链接失效（未取得描述）” |
| 采集信息 | `keywords` | 外部采集记录的关键词，不是经核验的完整岗位技能清单 |
| 采集信息 | `first_keyword` | 外部采集记录的首次关键词 |
| 采集信息 | `keyword_count` | 外部流程记录的关键词数量，不是岗位相关性评分 |
| 采集信息 | `is_guangzhou` | 外部采集的广州标记；当前城市筛选以 `location` 派生值为准 |

采集辅助字段的生成口径由外部采集流程负责，不能据此推断岗位完整职责或任职条件。

## 4. 原文与派生数据分离

**`description` 保留外部提供的原始招聘文字；清洗、分块和 Embedding 另外生成派生数据，不覆盖原文。**

- CSV 文件本身不由导入或索引流程回写。
- 导入时 `description` 不执行首尾空白裁剪；其他字段会裁剪首尾空白。这里保留的是 CSV 中解析出的正文，不是招聘网页 HTML 或网页字节快照。
- 数据库的 `raw` 保存导入字段，`normalized` 保存派生的城市、薪资、经验及质量标记等结构信息。
- 分块正文、章节与条件标签、原文偏移及可选向量保存在独立索引数据中；规则标签不等于已经核验的事实。
- 导入字段发生变化时记录新的岗位版本并保留历史记录。重建索引不会把清洗结果或模型解释写回原始 JD。

这样即使后续发现分块、规则标签或模型理解有误，仍然可以回到最初导入的 JD 和相应版本检查证据，再修正派生数据。

## 5. CSV 导入约定

- 使用 UTF-8 编码，兼容 UTF-8 BOM；必须包含表头。
- 当前导入器要求以下 11 列存在：`job_id`、`title`、`company`、`location`、`salary`、`experience`、`education`、`url`、`description`、`status`、`collected_at`。其余 5 列不是必需列。
- 同一次导入的 `job_id` 不得为空或重复，记录列数必须与表头一致；整个输入校验通过后才写入数据库。
- 多行正文、逗号和引号必须按标准 CSV 规则转义，不要用简单的文本行数计算岗位数。
- 允许正文为空，但会标记为缺失正文；不能把缺失信息补写成招聘方原文。
- `source` 由导入参数指定，默认 `boss`，不是当前 CSV 的一列。数据库以 `source:job_id` 标识岗位，不自动合并不同 ID 的近重复 JD。

在项目根目录、已配置本地环境后，可以仅导入而不构建索引：

```bash
.venv/bin/job-rag import data/jobs.csv --source boss --no-index
```

`--no-index` 将索引任务留待后续处理，不在此步骤触发 Embedding。构建索引前应确认模型配置与费用预算。

## 6. 采集状态与招聘状态不同

CSV 的 `status` 表示采集结果；知识库的 `job_status` 表示独立维护的招聘状态，两者不能混用。

- 新导入岗位的招聘状态为 `unknown`，只能称“未核验是否仍在招聘”。
- “已获取描述”不等于 `active`；“链接失效”也不会自动转成 `closed`。
- `active`、`suspected_expired`、`closed` 的变更需要通过独立状态管理流程记录依据。
- 某岗位没有出现在后续 CSV 中，不会因此自动关闭或删除。
