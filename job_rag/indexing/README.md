# 为什么保存成功的 JD 还不能立即参与检索？

当新职位导入数据库时，原文已经存在，但用于搜索的 Chunk 和向量可能还没生成。如果“保存资料”和“调用远程 Embedding”在一个事务里完成，外部 API 超时就会阻断数据保存；如果提前将岗位标为可检索，用户又可能拿到新文本配旧向量。

因此索引模块承担独立的第二阶段：**将已保存的某一版 JD 转成与它一致的可检索表示**。

## 一、为什么是可重试任务，而非导入函数中直接调用模型？

`preprocessing/importer.py` 在保存新岗位、内容字段变化产生新版本，或发现索引版本/签名过期时，调用 `tasks.enqueue()` 登记任务，任务包括 `job_key`、`version`、`signature`；这一动作和岗位写入处于同一数据库事务，但不请求模型。只有采集元数据或 CSV 列结构变化的刷新不会因内容变化登记任务（索引版本/签名过期时仍会登记重试），因为检索文本没有改变。导入完成意味着来源记录已可靠保存，**不意味着索引已就绪**。

假设某岗位更新两次：v1 排队时，v2 已经导入。如果 v1 的慢速 Embedding 请求最后返回，而系统不检查任务版本，就会覆盖 v2 证据。Worker 在处理前检查版本和签名，写回时再次在事务中检查；已过时的任务标为 `obsolete`。这使网络调用完成先后不再决定哪个岗位版本生效。

## 二、Worker 为什么分成“准备”和“最终提交”两段？

`worker.py::run_index_tasks()` 先读待处理或失败任务，从当前原文调用[分块器](../chunking/README.md)生成 `Document(text, details)`，再通过[模型客户端](../providers/README.md)可选产生 Embedding。这一步可能较慢，也可能失败，不应先删除数据库中的全部旧块。

当文本与向量都准备好后，Worker 才在新的数据库事务中锁定岗位、复核版本、删除旧块、插入新块并更新 `indexed_version`、`index_signature` 与任务状态。这样避免出现“只写入一半新块，但已向用户宣称索引成功”。

~~~text
已保存的 v2 岗位 → pending 任务 → 分块、可选 Embedding（可能失败）
                                        ↓ 成功
                                   锁定并复核 v2
                                        ↓
                            同事务替换 chunks / 标记 done
~~~

失败时任务为 `failed`，记录错误类型和尝试次数，可下一轮重试；不会把供应商响应正文或凭据保存到任务表。

## 三、为什么不是所有更新都要重新花钱生成向量？

重新导入可能只更新采集日期；如果生成的所有检索块文本和索引签名仍然一致，新旧向量描述的是同一输入，可以复用。相反，如果更换了 Embedding 模型、维度、分块算法或预算，即使 JD 没变也不应混用旧表示，因为向量空间或文本语境可能已经变化。

`config.py` 把这些关键配置组合成索引签名；Worker 检查签名一致，并对最终生成的文本列表做相等比较。**复用判断基于真正用于索引的文字，不是“岗位 ID 一样”就随意复用。**

没有配置 Embedding 时也可完成 Chunk 索引，`embedding=None`，后续走 BM25；配置后 `worker` 等命令可能产生真实模型调用与费用。

## 四、为什么这是单写入者而不是常驻队列？

`job-rag worker` 扫描 `pending/failed` 并运行一轮就退出，没有多进程队列领取、分布式锁与定时调度。对当前几百条职位，设计简单、可观察且易恢复；代价是需要人工或受控定时任务触发，且不能并发运行多个写入者。

~~~bash
job-rag import data/jobs.csv --no-index
job-rag worker
# 解析或模型配置改变时
job-rag reindex
~~~

如果旧库新增了 `chunks.details` 等表结构，需先备份、显式运行 `job-rag migrate`，再按配置重建。**代码拆分本身不需要迁移，数据 schema 变化才需要。**

读这个目录时应看到的是一条状态机：`pending → done/failed/obsolete`。`tasks.py` 登记任务，`worker.py` 进行可失败的加工和可靠提交；最终由[检索模块](../retrieval/README.md)只读取已匹配当前版本的索引。
