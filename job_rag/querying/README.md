# 精确数据查询与共享过滤

本目录负责确定性、可解释的数据访问，不依赖 BM25、Embedding 或 Chat，也不依赖 `retrieval/`。

| 文件 | 职责 |
|---|---|
| `filters.py` | `StructuredFilters` 与 `matches()`：检索和全库查询共用的硬条件模型与判断规则 |
| `catalog.py` | 全库字面匹配、计数、一致性分页、语料指纹与批量全文读取 |
| `jobs.py` | 岗位全文、版本/状态历史与语料/索引统计，不包含 HTTP 异常或鉴权 |

岗位序列化统一使用 `storage/serialization.py`，不从检索模块借用输出函数。数据库访问使用 `storage/` 的模型。

## 字面计数与分页

`catalog_query()` 对一个有序 SQL 读取结果在应用层遍历，不要求索引已就绪。支持标题/描述字段、AND/OR、大小写规则及 substring/token 匹配；`terms=[]` 表示枚举结构和状态条件内全部岗位。

`matched_jobs` 是当前条件下的完整字面计数；`eligible_jobs` 是字面匹配前的范围，另返回缺失正文数及状态分布。这不能证明“岗位将某技能作为必备要求”。

后续页必须传相同条件、`snapshot_id` 与返回的 `next_offset`。数据或条件变化返回冲突，由 API 映射为409；必须从头重来，不能混合新旧结果。这是变化即中止的乐观校验，不是保留永久历史快照。

`batch_jobs()` 每批读取1—20份全文，支持 `corpus_id` 绑定数据范围，以及按岗位版本拒绝不匹配的读取。缺失岗位和版本变化逐项返回错误；历史关闭岗位不会被偷偷隐藏。

## 公共硬条件

城市、区、薪资周期/区间、求职者经验、学历、实习类型及字面必含词均复用同一套规则。`skills` 是字面AND，不表示语义必备条件；招聘状态过滤按各查询契约执行，默认不把unknown说成在招。

`knowledge_base_stats()` 的 indexed 数量是索引就绪统计，不是相关岗位数；`job_detail()` 返回岗位全文及历史，不负责推荐是否合适。接口鉴权由[interfaces](../interfaces/README.md)负责。

完整参数和统计口径见[任务路由与字面查询契约](../../docs/task-routing.md)。语义全量统计尚未形成自动化闭环；只提供完整枚举和批量全文读取，不以 Top-K 或字面计数冒充语义统计。
