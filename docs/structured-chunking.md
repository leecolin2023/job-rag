# 结构化分块与索引迁移

## 源文可追溯的派生结构

`job_rag/chunking.py` 生成 `Document(text, details)`；`normalize.documents()` 保留文本列表兼容接口，原算法保留为 `legacy_documents()` 用于对照实验。

1. 识别职责、任职要求、加分项、福利、公司介绍及 unknown 章节。支持编号、Markdown、中文方括号和标题异常换行，如 `【岗位\n职责】`；不在普通句子内部寻找标题。
2. 章节内优先保留编号条目及其续行，不在 `Python或Java` 等逻辑表达中机械切开。
3. 条件标签包括 `required / preferred / not_required / mixed / unspecified`。带例外、要求与优先条件混合的条目保守标记 mixed；不强行拆成多个必备技能。
4. 不跨岗位、章节及不同条件标签组合。超长条目优先按句子分开，最后才硬切；保留条目源位置、continuation_id 和 hard_split 标志。
5. 每个分块保存原文起止偏移、章节及标题偏移、原始正文、标签方法、解析版本、分块版本和实际预算单位。

源文偏移使用 Python Unicode 码点计数（`source_offset_unit=unicode_codepoints`），不是UTF-8字节或JavaScript UTF-16下标。

这些是**规则推导的注释**，不是已经经过人工核验的业务事实。无标题文本保留 unknown；复杂条件不做逻辑蕴含判断。标题/条件识别错误需通过人工抽查和检索评测发现。

## 向量文本与元数据分离

新方案向量文本包含岗位标题、章节、可选条件性质提示和原文；公司、薪资、地区、学历等仍保留在事实库与返回结果中，不重复灌入每个向量。

仅薪资或采集日期改变、向量文本相同且模型签名相同时，可复用既有向量。原始记录仍产生新版本，不丢失字段变化。

预算支持：

| 配置 | 含义 |
|---|---|
| `CHUNK_BUDGET_UNIT=chars` | Unicode字符数，不是 Token 数；结构化方案计入上下文头部 |
| `utf8_bytes` | UTF-8字节预算，保守代理量，不冒称模型 Token 数 |
| `tokens` | 使用本地 tokenizer JSON，需先安装 experiments 依赖并设置 `TOKENIZER_PATH` |

没有假设旧 Qwen tokenizer 等同于托管 Qwen3.7 tokenizer。实验默认明确使用字符预算；真实 Token 消耗以百炼 usage 为准。不要将“1100字符”写成“1100 Tokens”。

## 检索证据上下文

查询结果新增 `evidence_details`，返回命中块的章节/条件性质与原文位置；另外提供任职要求和加分项 `qualification_context`，总预算3600字符。若截断，明确标记 `truncated`，完整文本仍通过岗位详情获取。Chat生成接口也会收到这些上下文。

现有 `skills` 仍表示标题/原文中必须字面出现的条件，不会自动变为“岗位必须要求该技能”。自动区分技能必备/加分并执行布尔筛选尚未实现，不应误用派生标签证明一个复杂条件。

## 显式数据库升级

`chunks` 新增可空 `details JSON` 字段；迁移保留岗位、历史状态和旧向量，并记录 `002_chunk_structure`。已有数据库缺少字段时启动会提示迁移，不会静默改表。

```bash
# 先备份；不要与写入任务同时操作
job-rag migrate
job-rag reindex
```

索引签名包含解析/分块版本、策略、预算单位、大小及本地 tokenizer 文件哈希。新旧签名不兼容，旧索引不会被当成新索引使用。

**当前线上容器尚未升级/切换**：离线实验不会写入它的数据库。实验完成后再按以下方式发布：

1. 备份数据库，保留旧镜像和配置，确认维护/回滚窗口。
2. 在独立数据库或恢复副本中验证迁移、重建与MCP查询；不要直接拿业务库做对照实验。
3. 使用候选版本镜像运行迁移，配置选定分块与 Embedding，再构建完整候选索引。
4. 验证数据量、状态过滤、检索证据及人工样例后切换服务；本版没有在线蓝绿索引切换管理器。

迁移是增量 schema 升级，不会自动创建第二套索引供不停机切换。单库直接 reindex 时，旧签名岗位会暂不参与查询，因此生产切换应使用独立候选库或维护窗口。
