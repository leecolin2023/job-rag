# BOSS 招聘岗位数据重建：采集与入库规范（2026-10-28）

## 目标与边界

- 不再使用旧 Google Sheet 作为采集总表；`data/jobs.csv` 目前是 593 条岗位的**历史基线**，本轮不覆盖、不删除。
- **正式岗位库**继续由 Job-RAG 的导入、版本、检索与查询组件维护，不在浏览器或 Google Sheet 中建立第二份“真相”。
- 搜索卡片 ≠ 完整职位详情；出现于搜索结果 ≠ JD 明确要求该技术；抓不到 ≠ 岗位已下线。
- 此目录记录当前浏览器已加载且可读取的搜索结果，不代表平台所有职位，更不能用于推断市场岗位总量。

## 新数据链路

```text
BOSS 直聘搜索页（按词、按城、按批次）
    └─ search_hits.csv 关键词命中快照（不丢弃重复命中）
         └─ 按 (source, job_id) 去重得到“待补详情”队列
              └─ 读取职位详情页完整 JD，保留来源与时间
                   └─ 校验、分离原文与派生字段
                        └─ job-rag import ... --source boss --no-index
                             └─ job-rag worker
```

**必须分离的四种信息**

| 数据 | 粒度 | 用途 |
| --- | --- | --- |
| 搜索命中 `search_hits.csv` | 采集批次 × 城市 × 关键词 × 岗位 ID × 排名 | 追溯搜索覆盖率、不同关键词命中；同一岗位可出现多次 |
| 岗位当前版本 | 来源 × 岗位 ID | 保存最新已核验标题、公司、地址、薪资、完整 JD；按内容变化保留版本 |
| 采集运行日志 | 批次 × 关键词 | 实际已读数量、加载限制、失败原因、未完成范围 |
| 技术/岗位语义分析 | 岗位版本 × 规则/模型版本 | 从 JD 判断平台、推理、Agent、RAG 等职责与技能条件；不能反写原文 |

## 输入质量门槛

1. **身份**：必须能从原始岗位链接严格提取 `job_id`；对同一个采集源以 `job_id` 识别岗位。同名同公司但 ID 不同不能自动合并。
2. **原文**：`description` 只保存真实读取到的完整 JD。无法取得时置空，并记录原因；不从搜索标题反推岗位要求。
3. **缺失**：没有展示的字段用空值/NULL + 缺失原因；不使用 `8`、`页面未显示` 等伪业务值。尤其不要把不能识别的字体编码工资解析为数值。
4. **位置**：分别保留搜索城市与岗位实际工作地；搜索“广州”不等于岗位一定在广州。
5. **状态**：`capture_status`（本次采集结果）、`detail_status`（JD 有无）和 `job_status`（是否在招）不能混用。缺失于下一次快照不自动判定已关闭。
6. **证据**：每条保存来源链接、查询词、采集日期、批次；职位内容变更应另存版本，不覆盖原始证据。
7. **覆盖**：每次记录实际加载的数量、是否滚动/翻页、是否遇到验证码/页面无内容。**空结果未核验**不可作为“该关键词零职位”的统计分母。
8. **幂等**：重复运行只增补当前批次观察，不按标题和公司强行去重。导入前校验 UTF-8、CSV 引号换行、完整主键、描述覆盖率、异常值与重复 ID。

## 后续采集优先级

以搜索**具体可迁移工程能力**为主，再用 JD 原文判断具体职责，不仅根据关键词命中量确定岗位类型。

- 模型服务 / AI Infra：`vLLM`、`SGLang`、`MaaS`、`模型部署`、`推理服务`、`模型服务`、`AI网关`、`Kubernetes`、`GPU调度`。
- Agent 工程：`Agent`、`LangGraph`、`MCP`、`Agent Runtime`、`Harness`。
- 知识检索：`RAG`、`向量检索`、`Embedding`、`重排`、`知识库`。
- 行业专项：金融机构及金融科技子公司招聘公告应**单独采样**，与 BOSS 站内关键词搜索分开记录渠道。
