# 第一轮真实 Embedding 召回实验（2026-10-25）

## 运行范围

- 百炼北京业务空间，`qwen3.7-text-embedding-flash`，1024维；不是模拟向量。
- 592条有描述岗位，30条种子查询，按15个主题组拆分为dev 14条/test 16条。
- 五组文档方案采用同一查询与硬条件；无Rerank、无查询扩展、无Hybrid。
- 先对eligible分块做精确余弦计算，再按岗位取max分数并保留Top-50。
- 运行目录：`runtime/experiments/recall-20261025-v1/`；冻结准备快照为`prepared-20261025-v5`。

**以下是已知正例指标（seed），不是穷尽标注后的真实总体召回或准确率。** 每条查询目前只有一个来源可校验的种子正例，因此seed Recall@K也等于这些正例的HitRate@K。其他岗位未标注不代表不相关。

## 可得出的结论

1. **不能宣称Embedding全面胜过BM25。** 当前种子集包含技术词和较明确的岗位线索，BM25非常强；它不代表所有真实用户问法。
2. 结构化C在test中的正例前排位置更好，但dev没有相同改善。C相对A的test seed nDCG@5差值约+0.1399，主题组bootstrap 95%区间为[0, 0.28125]，触及0；样本只有8个test组，不能据此宣称稳定显著提升或直接上线。
3. D相对C添加条件提示并未改善本轮向量排名；提示文本可能影响相似度。条件性质仍应保留为可追溯元数据，用于证据解释和后续重排，而不是预设“提示越多召回越好”。
4. 缩小预算到E没有在当前主要seed指标上显示收益，不能以更多chunk数量证明更准确。
5. 不根据test挑选线上赢家。若下一轮必须从dense方案中固定一个基线，dev上的A仍是保守选择；BM25也应保留对照。尚未配置线上切换。

错误不是只有平均数：A的dev Top-10未覆盖`rag-01`、`harness-01`；C未覆盖`rag-01`、`marketing-02`。存在个别查询收益/退化相互抵消，需查看原始候选而不是只看平均Recall。

这些是公开价格估算，不是账户实际扣费。免费额度、折扣及429是否计费以平台账单为准。缓存已保留，不应为了重复查看报告重新生成向量。
